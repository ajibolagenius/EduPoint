# Assignment 02 — Tutor Notes

**100L · Semester 1 · Week 04 · The Campus Fair Workspace · For tutors**

## Purpose and scope

Use this with [Assignment 02](assignment-02.md), an individual take-home consolidation of Week 04.
Assignment 01 covered Weeks 1–3; this brief tests file operations, location-dependent paths, diagnosis
and tool readiness in a fresh workspace. It does not require Week 05 editor skills, HTML or Git workflows.

The curriculum's Week 04 deliverable is “Command-line drills; install the toolchain from an offline
installer”. This assignment gives students another opportunity to demonstrate those skills; it does
not introduce a new curriculum requirement or assessment category.

## Set up delivery

- Announce the deadline and exact class submission destination before distributing the brief.
  The suggested 90 minutes is take-home effort, outside the **120-minute class**.
- Confirm where the 10-point mark is recorded. Do not count the same practical evidence twice if
  the lab and assignment share a mark; explain the recording arrangement to students.
  Semester weights stay as published: weekly submissions together account for 10%.
- Give students the brief and Week 04 workbook, in print or offline files. When distributing Markdown,
  retain its relative paths to the Week 04 image assets. The PDF embeds the image and diagram.
- Check that each learner has a laptop turn or a booked shared/prepared station. Keep individual
  workspace names and evidence separate on shared machines.
- Use the preflighted, OS-matched offline installer kit described in the Week 04 lab. Installation
  happens outside the assignment workspace. No paid software, new account or online download is required.

## Installation evidence and access

Reuse is allowed only for a learner's **own earlier installation action**, labelled with its date.
The four application/version checks must be fresh. A working pre-existing installation should be kept;
arrange a prepared-station launch/unpack turn if the learner has never performed that action.

Record “observed only” or “blocked” honestly. Stop an individual blocker after three minutes and
arrange a suitable station. Mark unaffected evidence normally and keep affected practical criteria
pending. A paper trace or browser simulation supports feedback but is not execution evidence.
Do not replace a learner's keyboard turn with their partner's screenshot.

## Public repository boundary

This assignment is graded. **No worked solution, model command sequence, completed log, final answer
diagram or answer key belongs in this public repository.** Use the tutor team's private channel for
marking keys. These notes contain checking guidance only.

## Mark consistently

Use the student rubric: **2 + 3 + 2 + 2 + 1 = 10 points**. Accept commands valid for the student's
declared shell; there is no single required command sequence. Assess the required actions and evidence.
Do not require a specific sample version number or identical terminal formatting across platforms.

| Check | Look for | Ask the learner |
|---|---|---|
| Setup | A fresh workspace, initial listings and a recorded absolute location | “Which part of this path identifies the parent?” |
| Operations | Before/after evidence and individual command entries | “Which listing proves what happened to the source?” |
| Deletion | Exact target, confirmation and a check afterwards | “What did you inspect before confirming?” |
| Paths | Both routes tested from the same recorded location | “Where does this relative path begin?” |
| Diagnosis | Actual error, location/listing checks and a justified retry | “Which check supports your explanation?” |
| Toolchain | Personal installation action or pending status; four fresh checks | “What shows that this tool runs?” |
| Ownership | Predictions, results and explanations consistent with captures | “Show one operation again in a fresh practice folder.” |

The initial tree in the brief is the supplied starting specification. Students draw their own final
structure; do not distribute a completed one. Empty files are valid; written file contents are not
assessed. Avoid demanding recursive tree commands, scripts, Git, editor settings or other untaught tools.

## Brief individual check

Ask each learner to explain one path and demonstrate one operation on their workspace or a fresh
practice file. Never ask them to repeat deletion on valuable work. Observe what they type and ask
how they verified it. Keep the check brief and arrange catch-up separately from the class schedule.

If a capture and explanation conflict, request a repeat demonstration. Follow the institution's
process for suspected unaided-work breaches; writing style alone is not evidence of AI use.
